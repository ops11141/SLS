# تقارير الصيانة — SLS

واجهة عربية متجاوبة لتنظيم تقارير الصيانة، مستقلة عن مشروع توثيق الأعطال `mn`.

## أنواع التقارير
- تقرير وردية الصيانة (`shift`).
- تقرير الأعمال المجدولة (`scheduled`).
- الانقطاعات المتجاوزة 3 ساعات (`outage3`).
- الانقطاعات المتجاوزة 6 ساعات (`outage6`).

## الملفات
- `index.html`: الواجهة الأولية.
- `database/schema.sql`: مخطط قاعدة البيانات المقترح لمشروع Supabase مستقل.
- `.github/workflows/pages.yml`: سير عمل نشر GitHub Pages.

## مهم قبل الاستخدام المشترك
الواجهة الحالية تحفظ التقارير في `localStorage` على الجهاز/المتصفح الحالي فقط. لا تضع مفاتيح سرية في ملفات الواجهة. لم يتم إنشاء مشروع Supabase أو ربط الواجهة به بعد.

## إعداد قاعدة البيانات
1. أنشئ مشروع Supabase جديدًا مخصصًا لـ SLS من حسابك؛ لا تستخدم مشروع `mn`.
2. افتح SQL Editor في المشروع الجديد.
3. انسخ محتوى `database/schema.sql` وشغّله.
4. ارسل عنوان Project URL ومفتاح publishable/anon العام فقط عند متابعة ربط الواجهة. لا ترسل `service_role` أو أي secret key.
5. قبل تشغيل التقارير المشتركة، يجب تنفيذ شاشة تسجيل دخول وسياسات صلاحيات مناسبة للمستخدمين. المخطط الحالي يسمح بالقراءة والكتابة للمستخدمين المصادق عليهم فقط.

## GitHub Pages
افتح Settings → Pages وتأكد من تفعيل النشر باستخدام GitHub Actions. سير العمل موجود في `.github/workflows/pages.yml`. الرابط المتوقع بعد نجاح التفعيل: https://ops11141.github.io/sls/
